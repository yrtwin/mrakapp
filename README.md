# MRAK8 · Central Booking & Intake Center

## Памятка Git

Все команды выполняются в папке проекта (`C:GitProjectsmrakapp`): в терминале VS Code, Git Bash или PowerShell.

**Обычный цикл: сохранить изменения и отправить на GitHub**

```bash
git pull                  # 1. перед работой: забрать свежие изменения с GitHub
git status                # 2. посмотреть, какие файлы изменились (красные — не добавлены, зелёные — добавлены)
git add -A                # 3. добавить все изменения в коммит
git commit -m "Что сделал"  # 4. сохранить снимок с понятным описанием
git push                  # 5. отправить на GitHub
```

Описание коммита пишите по сути: `"Добавил вещдок #002"`, `"Поправил текст оферты"`, а не `"правки"`.

**Полезное**

| Команда | Что делает |
| --- | --- |
| `git diff` | показать, что именно поменялось в файлах (выход — клавиша `q`) |
| `git add README.md` | добавить в коммит только один файл |
| `git restore файл` | откатить файл к последнему коммиту (изменения в нём пропадут) |
| `git restore --staged файл` | убрать файл из коммита, сами изменения останутся |
| `git log --oneline` | история коммитов коротко (выход — `q`) |
| `git commit --amend -m "Новый текст"` | исправить описание последнего коммита, **только если ещё не сделали push** |

**Важно**

- `.env` (токены бота, оплаты, СДЭК) в git не попадает: он в `.gitignore`. Никогда не добавляйте его вручную (`git add -f .env`).
- Если `git push` отвечает `rejected` / `fetch first`, кто-то успел запушить раньше вас: сделайте `git pull`, потом снова `git push`.
- Если `git pull` пишет про конфликт (`CONFLICT`), Git не смог сам объединить правки в одном месте файла. Откройте файл, оставьте нужный вариант между `<<<<<<<` и `>>>>>>>`, удалите эти метки, затем `git add -A`, `git commit`, `git push`.
- После `git pull` с чужими изменениями перезапустите магазин: `npm run docker:public` (на Windows — `npm.cmd run docker:public`).

## Быстрый старт локально

Нужен Node.js 20+ (проверено на 24 LTS).

```bash
npm install
cp .env.example .env    # для локалки достаточно блока ниже
npm run dev             # API http://localhost:8080 + мини-апп http://localhost:5173
```

Минимальный `.env` для разработки без Telegram:

```
PUBLIC_URL=http://localhost:8080
WEBAPP_URL=http://localhost:5173
DEV_AUTH=1
ADMIN_IDS=1
SEED_DEMO=1
MEDIA_PUBLIC_URL=/media
```

- База — встроенная PGlite (`server/data/pglite`), ставить Postgres не нужно. При первом старте создаётся худи #001 из `mrakl-zip-front.jpg` / `mrakl-zip-back.jpg` (фото вырезаются из чёрного фона и режутся в AVIF/WebP 360–2400 px), с `SEED_DEMO=1` — ещё демо-дроп #002 и sold out #003.
- В браузере мини-апп работает в режиме эмуляции Telegram: нарисованы кнопки Telegram, пользователь — тестовый (`id=1`, он же админ при `ADMIN_IDS=1`), оплата — эмуляция формы, деньги не списываются.
- Полезные параметры: `?frame=1` (рамка iPhone: статус-бар, отступы), `?splash=full` / `?splash=0`, `?fresh=1` (пустой пакет), `#/admin` — Control room, `?startapp=product_1` — deep link.
- Тесты: `npm test` — весь путь оплаты на эмуляторе Bot API, резервы, админка, QR.

## Локально в Telegram: Docker + настоящий бот

Telegram открывает мини-апп только по https. Адрес `https://127.0.0.1` (этот компьютер) он принимает, поэтому сервер и домен для проверки не нужны. Магазин целиком работает в Docker: Postgres, API, бот, мини-апп и Caddy, который отдаёт https своим локальным сертификатом. Бот ходит в Telegram через прокси Docker Desktop, так что Happ должен быть включён.

1. В `.env` должны быть `BOT_TOKEN` и ваш Telegram id в `ADMIN_IDS`. Кнопки локального мини-аппа видят только админы, остальные видят обычный каталог в чате.
2. Откройте Docker Desktop, остановите `npm run dev`, если он запущен (бот не может работать в двух местах), и запустите `npm run docker:local`.
3. Один раз доверьте компьютеру сертификат магазина: `certutil -user -addstore Root mrak8-local-ca.crt` → «Да». Затем полностью закройте Telegram Desktop (трей → Выход) и откройте снова. Удалить сертификат потом можно в `certmgr.msc` → Доверенные корневые центры → Caddy Local Authority.
4. Telegram Desktop на этом компьютере → @mrak8_shop_bot → кнопка MRAK8 у поля ввода или `/start` → «ОТКРЫТЬ ЦЕНТР ОФОРМЛЕНИЯ».

Логи — `npm run docker:local:logs`, остановка — `npm run docker:local:stop` (база, фото и сертификат сохраняются в томах Docker). На телефоне и у других людей мини-апп заработает только после сервера с доменом.

## В интернет без сервера: `npm run docker:public`

То же, что `docker:local`, плюс туннель [localhost.run](https://localhost.run) в Docker: бесплатный публичный https-адрес без регистрации. Кнопка MRAK8 и «ОТКРЫТЬ ЦЕНТР ОФОРМЛЕНИЯ» работают у любого человека, сертификат не нужен.

- Работает, пока включены этот компьютер, Docker и Happ. Через Happ идёт соединение туннеля, поэтому посетители видят IP VPN, а не ваш домашний (localhost.run пишет IP в заголовок `x-backend-addr`). Без Happ туннель не поднимется. `DOCKER_TUNNEL_PROXY=` (пусто) в `.env` подключает напрямую, и тогда виден ваш IP.
- Адрес меняется при каждом переподключении. Бот сам переставляет кнопку MRAK8 всем, кто ему писал, а кнопки в старых сообщениях перестают работать: достаточно снова отправить `/start`.
- **Ограничение:** у многих российских провайдеров зарубежные хостинги режутся — файл больше ~16 КБ замирает, и мини-апп без VPN не догружается. С VPN грузится полностью. Чтобы открывалось у всех без VPN, нужен адрес в России: сервер или платный российский туннель.
- Остановить — `npm run docker:local:stop`. Вернуться к режиму «только этот компьютер» — `npm run docker:local`.

## 1. Бот в @BotFather

1. `/newbot` → имя и username (например `mrak8_bot`) → получите **BOT_TOKEN**.
2. `/mybots` → бот → **Bot Settings → Configure Mini App → Enable Mini App** → URL мини-аппа (`WEBAPP_URL`, только https). Так бот получает Main Mini App, а ссылка `https://t.me/mrak8_bot?startapp=…` открывает его сразу.
   Альтернатива: `/newapp` → короткое имя `shop` → ссылка `https://t.me/mrak8_bot/shop`. Любую из ссылок впишите в `MINIAPP_LINK`.
3. **Bot Settings → Inline Mode → Turn on** — карточка «Я оформлен в MRAK8» уходит через `shareMessage` как inline-сообщение «via @бот». Если «Поделиться» не срабатывает, мини-апп откроет обычный экран пересылки ссылки.
4. Кнопку меню, команды `/start` и `/admin` и вебхук сервер настраивает сам при старте (или вручную: `npm run bot:setup`).
5. Свой Telegram id (для `ADMIN_IDS`) подскажет `@userinfobot`. Для уведомлений о заказах создайте группу, добавьте бота, id группы (начинается с `-100`) — в `ADMIN_CHAT_ID`.
6. Канал: добавьте бота администратором с правом публикации, в `CHANNEL_ID` — `@username` канала.

## 2. Оплата: ЮKassa через Telegram Payments

Товары физические, поэтому Telegram Stars не подходят — используется Telegram Payments с провайдером.

**Тестовый режим** (без денег):
1. `@BotFather` → `/mybots` → бот → **Payments** → **ЮKassa** → **Connect ЮKassa: Тест**.
2. Скопируйте токен вида `381764678:TEST:12345` в `PAYMENT_PROVIDER_TOKEN`.

**Боевой режим:**
1. Заключите договор с ЮKassa (yookassa.ru), подключите магазин и **онлайн-кассу «Чеки от ЮKassa»** (или свою кассу) — без неё чек по 54-ФЗ не уйдёт.
2. В `@BotFather` → Payments → ЮKassa → **Connect ЮKassa: Live**, привяжите магазин, получите боевой токен.
3. Укажите ставку НДС `RECEIPT_VAT_CODE` (справочник vat_code ЮKassa; 1 — «без НДС») и при необходимости `RECEIPT_TAX_SYSTEM_CODE`. Значения согласуйте с бухгалтером.

Как это устроено (`server/src/services/orders.ts`, `payments.ts`, `bot/index.ts`):
- клиент отправляет только id товаров, размеры, количество и протокол — **цены и остатки сервер берёт из базы**;
- заказ создаётся со статусом `pending`, вещи резервируются на `RESERVE_MINUTES` (15) — атомарным `UPDATE … WHERE stock - reserved >= qty`, без перепродаж; у одного субъекта не бывает двух резервов;
- `createInvoiceLink` (RUB, позиции и доставка в `prices`, чек в `provider_data.receipt`: items, vat_code, payment_mode, payment_subject, телефон покупателя); Telegram спрашивает телефон в форме оплаты и передаёт провайдеру (`need_phone_number` + `send_phone_number_to_provider`);
- `pre_checkout_query`: сверка суммы, валюты и резерва (истёкший резерв пробуем взять заново), ответ за доли секунды;
- `successful_payment`: заказ → `paid`, списание остатков, сохранение `telegram_payment_charge_id` и `provider_payment_charge_id`, квитанция покупателю, уведомление в `ADMIN_CHAT_ID`. Повторные апдейты ничего не делают дважды;
- неоплаченные резервы снимает фоновая задача раз в 30 секунд.

**Сменить провайдера:** `PAYMENT_PROVIDER=tbank|cloudpayments` и токен из @BotFather. Формат чека в `provider_data` у них свой — допишите его в `buildProviderData()` в `server/src/services/payments.ts` по документации провайдера (там помечено TODO); без него оплата работает, но чек нужно формировать на стороне провайдера.

## СДЭК: расчёт, отправления, трек-номера

С `CDEK_MODE=test` или `live` способ «СДЭК» в протоколе работает через API СДЭК:
- покупатель вводит город, выбирает **пункт выдачи** из списка или **курьера до двери** и сразу видит цену и срок от СДЭК. Цену сервер считает сам, клиенту не доверяет;
- после оплаты заказ сам создаётся в СДЭК («Посылка склад-склад / склад-дверь»: вы сдаёте посылку в пункт `CDEK_SHIPMENT_POINT`);
- каждые 2 минуты бот забирает у СДЭК номер и статусы: номер становится трек-номером; когда СДЭК принял посылку, заказ «этапирован» и покупатель получает трек и кнопку «Отследить»; о прибытии в пункт выдачи и вручении бот тоже пишет;
- в Control room → «Заказы» у заказа видно ПВЗ, номер и статус СДЭК, кнопка **«Накладная в чат»** присылает PDF для печати, **«Передать в СДЭК»** — повтор, если СДЭК был недоступен.

`test` — тестовый сервер СДЭК с общими ключами из документации: всё работает, но посылки не настоящие. Для боевого режима: договор со СДЭК → lk.cdek.ru → «Интеграция» → ключ (Account и Secure) в `CDEK_ACCOUNT` / `CDEK_SECURE`, `CDEK_MODE=live`, код вашего пункта приёма в `CDEK_SHIPMENT_POINT`.

## 3. Домен и HTTPS

Telegram открывает мини-апп и шлёт вебхуки только по **https**.

**Вариант А — один VPS** (проще всего): Docker + docker compose, A-запись домена на IP сервера.

```bash
git clone … && cd MRAKAPP
cp .env.example .env     # заполните, см. раздел 4
echo "DOMAIN=shop.mrak8.ru" >> .env
docker compose up -d --build
curl https://shop.mrak8.ru/api/health
```

Поднимутся PostgreSQL, приложение (API + бот + мини-апп с одного домена, `SERVE_WEB=1`) и Caddy с автоматическим сертификатом. `PUBLIC_URL` и `WEBAPP_URL` compose подставит как `https://DOMAIN`. Вебхук `https://DOMAIN/telegram/webhook` сервер зарегистрирует сам. Фото хранятся в volume `media` (`STORAGE_DRIVER=local`) или в S3.

**Вариант Б — раздельно:** фронт на Vercel/Netlify (`npm run build -w web`, папка `web/dist`, переменные `VITE_API_URL=https://api.…`, `VITE_MINIAPP_LINK`), бэкенд на Railway/Render/VPS (`npm run build -w server && npm start`, Node 20+). Тогда `WEBAPP_URL` — домен фронта (попадёт в CORS), `PUBLIC_URL` — домен API.

После деплоя впишите `WEBAPP_URL` в @BotFather (шаг 1.2).

## 5. Тестовая оплата от начала до конца

1. Тестовый токен ЮKassa в `PAYMENT_PROVIDER_TOKEN`, сервер задеплоен по https.
2. Откройте бота → `/start` → **«ОТКРЫТЬ ЦЕНТР ОФОРМЛЕНИЯ»**.
3. Сплэш → лента → худи #001 → выберите рост на ростомере → **«ИЗЪЯТЬ»** → **«ОФОРМИТЬ ПРОТОКОЛ»** → заполните протокол → **«ОПЛАТИТЬ»**.
4. В форме Telegram введите тестовую карту ЮKassa **1111 1111 1111 1026**, любой будущий срок, CVC **000**.
5. Проверьте: экран «ОФОРМЛЕН» со штампом и QR; сообщение-квитанция от бота; уведомление в `ADMIN_CHAT_ID`; заказ в Control room (`/admin`) со статусом «ПРИНЯТ»; остаток размера уменьшился.
6. В Control room → Заказы впишите трек-номер → покупателю придёт сообщение, статус станет «ЭТАПИРОВАН».

## Админка Control room

`/admin` в боте или `#/admin` в мини-аппе (только для `ADMIN_IDS`):
- стена мониторов: выручка за день и 7 дней, заказы, средний чек, топ, остатки на исходе;
- товары: создание и редактирование, фото ФАС/СПИНА/детали (перетаскивание или выбор с телефона, кадр 4:5 / 1:1, вырезка чёрного фона, AVIF/WebP + LQIP на сервере), размеры с остатками и диапазоном роста для ростомера, замеры, протокол осмотра, статусы (черновик / дроп скоро / в продаже / sold out / архив);
- дропы: статус «ДРОП СКОРО» + дата выхода → в каталоге обратный отсчёт и «Уведомить меня», в момент дропа бот пишет всем подписавшимся;
- заказы: фильтры, смена статуса, трек-номер с уведомлением, CSV (в Telegram файл присылает бот);
- доставка: список способов и цены;
- канал: пост с фото и кнопкой, которая открывает мини-апп сразу на товаре (`startapp=product_<id>`).

## Как устроен проект

Раздел для разработчика: как всё связано, где что лежит, как безопасно менять.

### Коротко

- **Монорепозиторий** на npm workspaces из трёх пакетов: `shared` (общие типы и функции), `server` (API, бот, оплата, СДЭК), `web` (мини-апп). Везде TypeScript.
- **Сервер — один процесс.** HTTP API, Telegram-бот и раздача собранного мини-аппа (`SERVE_WEB=1`) живут в одном Node-процессе, поэтому деплой — один контейнер плюс Postgres.
- **Мини-апп — SPA на React** без серверного рендеринга. Внутри Telegram он работает с настоящим `window.Telegram.WebApp`, в обычном браузере (`npm run dev`) — в режиме эмуляции: нарисованные кнопки Telegram и тестовый пользователь.
- **Источник правды — база.** Цены, остатки и стоимость доставки считает только сервер: клиент присылает id товаров, размеры и количество.

```
 Telegram-клиент ──► мини-апп (web/, React) ── HTTP /api ──►┐
        │             Authorization: tma <initData>         │
        └── чат с ботом ◄── Bot API ◄── polling / webhook ──┤  server/ (Fastify + grammY)
                                                            ├──► Postgres или PGlite (Drizzle)
                                                            ├──► ЮKassa (через Telegram Payments)
                                                            ├──► СДЭК API v2
                                                            └──► фото: диск или S3 (sharp → AVIF/WebP)
```

### Стек

| Часть | Технологии |
| --- | --- |
| Мини-апп | React 19, Vite, zustand (состояние), Web Animations API (анимации), шрифты @fontsource |
| Сервер | Fastify 5, grammY (бот), Drizzle ORM, PostgreSQL / PGlite (встроенный Postgres для разработки), zod (валидация), sharp (фото) |
| Общее | `shared/` собирается вместе с сервером и мини-аппом, отдельно не публикуется |
| Тесты | vitest + фейковый Bot API (`server/test/fake-bot-api.ts`) |
| Запуск | Docker Compose: `docker-compose.yml` (сервер с доменом), `docker-compose.local.yml` (этот компьютер и туннель) |

### Главные сценарии

**1. Вход в мини-апп и авторизация.** Telegram открывает мини-апп и передаёт `initData`, подписанную токеном бота. Каждый запрос к `/api` несёт заголовок `Authorization: tma <initData>`. Сервер (`app.ts` → `auth.ts`) проверяет подпись HMAC-SHA256, срок жизни (`INIT_DATA_MAX_AGE`), заводит или обновляет пользователя и кладёт его в `req.tg`. Админ — это просто id из `ADMIN_IDS`. Первый запрос мини-аппа `GET /api/bootstrap` отдаёт сразу всё: профиль, товары, доставку, настройки.

**2. Заказ и оплата.**
1. `Protocol.tsx` отправляет `POST /api/orders`: товары, размеры, ФИО, телефон, выбранную доставку.
2. Если это СДЭК, `shipping.ts → priceCdek` до транзакции считает цену у СДЭК и проверяет, что ПВЗ из этого города.
3. `orders.ts → createOrder` в одной транзакции отменяет прошлый неоплаченный заказ субъекта, резервирует остатки (`UPDATE … WHERE stock - reserved >= qty`, без перепродаж) и создаёт заказ `pending` с резервом на `RESERVE_MINUTES`.
4. `payments.ts → buildInvoice` собирает счёт с чеком 54-ФЗ, бот вызывает `createInvoiceLink`, мини-апп открывает форму оплаты Telegram (`openInvoice`).
5. Telegram присылает боту `pre_checkout_query`: `preCheckout` сверяет сумму и резерв и отвечает за доли секунды.
6. `successful_payment` → `markPaid`: заказ `paid`, остатки списаны. Повтор апдейта ничего не делает дважды. Бот присылает квитанцию, уведомляет `ADMIN_CHAT_ID`, а для СДЭК передаёт заказ в СДЭК (`registerShipment`).

**3. Фоновые задачи (`jobs.ts`).** Каждые 30 с снимаются истёкшие резервы и запускаются дропы: бот пишет всем, кто нажал «Уведомить». Каждые 2 мин у СДЭК запрашиваются номера и статусы (`syncShipments`): номер становится трек-номером, «принят СДЭК» → заказ «этапирован», «в ПВЗ» и «вручён» → сообщения покупателю.

**4. Публичный адрес без сервера (`docker:public`).** `docker/tunnel.sh` держит SSH-туннель localhost.run и пишет его адрес в общий том. `publicUrl.ts` замечает новый адрес, проверяет `/api/health` через туннель и вызывает `setPublicUrl` и `setupBot`. Бот переставляет кнопки меню (`syncMenus`) и переписывает кнопки в старых сообщениях (`appButtons.ts`).

**5. Кнопка меню бота.** После `/empty` в @BotFather общая кнопка через API не меняется, поэтому кнопка MRAK8 ставится каждому чату отдельно: при первом сообщении (`giveMenu`) и при смене адреса (`syncMenus`). При локальном адресе `127.0.0.1` кнопки видят только админы (`canOpenWebApp`).

### База данных (`server/src/db/schema.ts`)

| Таблица | Что хранит |
| --- | --- |

| `delivery_methods` | способы доставки: ключ, название, цена, нужен ли адрес, включён ли |
| `orders` | заказы: номер `MRK-…`, статус, payload счёта, ФИО, телефон, доставка и адрес, суммы, резерв, id платежей Telegram и ЮKassa, трек, данные СДЭК (`cdek`) |

### API

Мини-апп (`routes/public.ts`, нужна подпись Telegram):

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/bootstrap` | всё для старта: профиль, товары, доставка, настройки |
| `GET /api/products/:id` | один товар |
| `POST /api/me/height` | запомнить рост субъекта |
| `GET /api/cdek/cities?q=` · `/points?city=` · `/quote?city=&mode=&qty=` | СДЭК для протокола: города, пункты выдачи, цена |
| `POST /api/orders` | создать заказ и счёт |
| `GET /api/orders`, `GET /api/orders/:no` | мои заказы, один заказ |
| `POST /api/orders/:no/cancel` | отменить неоплаченный |
| `POST /api/drops/:id/watch` | подписаться на дроп |
| `POST /api/share/:no` | подготовить сообщение «Я оформлен» |
| `GET /api/dj` | плейлист DJ-сета |
| `GET /dj/:id` | сам трек; без подписи (тег `<audio>` не шлёт заголовки), поддерживает Range |
| `POST /api/dev/pay/:no` | только вне production: эмуляция оплаты |
| `GET /api/health` | проверка живости (без подписи) |

Control room (`routes/admin.ts`, префикс `/api/admin`, только `ADMIN_IDS`): `dashboard`, `products` (список, создание, правка, удаление, фото и их порядок, анонс в канал), `orders` (список, `PATCH` статуса и трека, `cdek` — передать в СДЭК, `waybill` — накладная в чат, `orders.csv` и `orders/export`), `delivery`, `drops`.

### Бот

- `/start [параметр]` — каталог в чате. `product_<id>` → карточка товара, `order_<no>` → кнопка «ОТКРЫТЬ ДЕЛО» владельцу заказа, остальное → каталог.
- `/dj` (админы) — плейлист DJ-сета: порядок и удаление. Чтобы добавить трек, админ присылает боту mp3 (как аудио или файлом, до 20 МБ).
- `/admin` — кнопка в Control room или «ДОСТУП ЗАПРЕЩЁН» с id субъекта (его вписывают в `ADMIN_IDS`).
- Кнопки каталога: `p:<id>` (карточка), `s:<id>:<размер>` (протокол изъятия), `info:delivery`, `info:about`, `menu`.
- Оплата: `pre_checkout_query`, `successful_payment`.
- Режимы: polling (локально и в Docker) или webhook (`/telegram/webhook`, сервер с https).

### Мини-апп

- **Маршруты** (hash, `lib/router.ts`): `#/` каталог, `#/case/:id` товар, `#/bag` пакет, `#/protocol` оформление, `#/booked/:no` «Оформлен», `#/dossier` досье, `#/admin/:tab` пульт (`products`, `orders`, `drops`, `delivery`, `channel`), `#/admin/p/:id` редактор. Ссылка с `startapp=product_1` при открытии превращается в `#/case/1` (`App.tsx → initialRoute`).
- **Состояние:** `lib/store.ts` (zustand). Пакет, рост и число визитов сохраняются в CloudStorage Telegram (в браузере — в localStorage).
- **Кнопки Telegram:** экраны объявляют их через `useMainButton(main, secondary)`. В Telegram это нативные кнопки, в браузере их рисует `EmuBottom`.
- **Стили:** токены в `styles/tokens.css`, всё остальное в `styles/app.css`, сгруппировано по экранам. Анимации — только transform и opacity, с учётом «уменьшения движения» (`?rm=1`).

### Проверки

- `npm test` — сквозные тесты сервера на поддельном Bot API: заказы, резервы, оплата, бот, Control room, СДЭК, туннель, ссылки.
- `npm run typecheck` — типы сервера и мини-аппа.
- `web/tools/tg-host.html` — стенд, который изображает Telegram Desktop. Ловит ошибки, которых нет в браузерной эмуляции, например пустой текст нативной кнопки.

### Как вносить изменения

- **Новое поле товара:** `db/schema.ts` → `npm run db:generate` → тип в `shared/src/index.ts` → `services/catalog.ts` (отдать в API) → zod-схема в `routes/admin.ts` → поле в `screens/admin/Editor.tsx` → показ на экране.
- **Новый экран:** имя и разбор пути в `lib/router.ts` → `case` в `Screen` (`App.tsx`) → при необходимости вкладка в `TAB` и `components/shell.tsx`.
- **Новый запрос к серверу:** маршрут в `routes/public.ts` (пользователь уже в `req.tg`) → тип в `shared` → функция в `web/src/lib/api.ts`.
- **Тексты бота:** `bot/catalog.ts` (каталог, доставка, «О магазине») и `bot/index.ts` (квитанция, уведомления, `/admin`).
- **Тексты оферты и политики:** `web/public/offer.html`, `privacy.html`.
- **Выкатить изменения:** `npm run test && npm run typecheck`, потом `npm run docker:public`. Работающий туннель не трогается, адрес не меняется.

### Подводные камни

- **Нативные кнопки Telegram** выбрасывают ошибку на пустой текст или текст длиннее 64 символов, и экран падает чёрным. Пустую кнопку `telegram.ts` просто скрывает. Две кнопки рядом обрезают текст, поэтому вторая по умолчанию ставится сверху.
- **iPhone (WebKit)** рисует анимированные элементы даже на обратной стороне повёрнутого блока. Поэтому метки невидимой стороны фото скрываются явно.
- **Ссылки `t.me/<бот>?startapp=`** работают только у бота с главным мини-аппом в @BotFather. Без него — ошибка «bot invalid». Ссылки строит `deepLink()` в `shared`: для обычного бота это `?start=`.
- **Кнопки web_app** принимают только https. Исключение — тестовая среда Telegram (`TELEGRAM_ENV=test`). `https://127.0.0.1` Telegram принимает, но открыть его можно только на этом компьютере.
- **Цены и остатки** — только из базы, доставка СДЭК — только расчёт сервера. Никогда не берите суммы из запроса клиента.
- **Заголовки HTTP** — только латиница. Кириллица в `X-Dev-User` кодируется `encodeURIComponent`.
- **`NODE_ENV` не пишите в `.env`:** Vite читает этот файл и собрал бы отладочную версию. Production выставляет docker-compose.
- **Telegram API у этого провайдера** доступен только через VPN-прокси (`TELEGRAM_PROXY`). Зарубежные хостинги и туннели обрезаются на ~16 КБ, у покупателей без VPN мини-апп с них не грузится.
- **Переводы строк:** `.gitattributes` держит LF. Скрипт `docker/tunnel.sh` с виндовыми переводами сломался бы в Linux-контейнере.
- **Windows:** если PowerShell блокирует `npm`, запускайте `npm.cmd`.

- [ ] Тексты `web/public/offer.html` и `privacy.html` — это шаблоны, заполните реквизиты и согласуйте с юристом.
- [ ] Ставка НДС и система налогообложения для чека.
- [ ] Фоновые задачи (резервы, дропы) рассчитаны на один экземпляр сервера. Для нескольких — вынесите их в отдельный воркер.
- [ ] Возвраты денег делаются в кабинете ЮKassa, статус заказа меняйте на «ОТМЕНЁН» вручную.
